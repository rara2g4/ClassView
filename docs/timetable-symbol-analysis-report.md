## 結論

実Excel内では、角括弧・丸括弧・隅付き括弧が一貫して異なる用途で使われていた。

- `[A]`〜`[D]`: 授業の段階・区分とみられる表記。`組`表記はなく、同一科目でA/CまたはB/Dが使い分けられる例がある。正式な学校ルールとは断定せず、中立名 `courseVariantTags` で保持する。
- `(1組)` / `（A組）` 等: 受講グループ候補。実データには裸の `(A)` はなく、全件が `組`を含む表記だった。
- `【CDP】` / `【専任】` / `【複数】` 等: 講師情報・講師表記。個人名とは限らないため、講師「情報」として扱う。
- `(2年)`、`（総合学習）` 等: 丸括弧だがグループではない。科目名側へ残す。

仮説に直接反する例は見つからなかった。ただし、`[]`の業務上の正式名称と、丸括弧alias同士が同一グループかどうかは学校担当者の確認事項として残る。

### `[]` の使用傾向

連続表記は `[A]` 214 entry、`[A][B]` 57、`[A][C]` 58、`[B]` 141、`[B][D]` 228、`[C]` 78、`[D]` 71だった。同一ベース科目で異なる表記が確認できた例は以下。

- `After Effects[A]` 29件 / `After Effects[C]` 29件
- `ゲームデザイン[B]` 14件 / `ゲームデザイン[D]` 14件
- `デッサン[B]` 14件 / `デッサン[D]` 14件

角括弧を消すとこれらを区別できないため、`subjectName`とcourse mapping keyに角括弧付き表記を残す。

## 採用したデータ構造

- `subjectRaw`: Excelセルの元表記をそのまま保持する。
- `subjectName`: 講師・受講グループ・status記号を除くが、course variantと通常の科目修飾は残す。
- `subjectBaseName`: `subjectName`からcourse variantも除いた基底名。
- `courseVariantTags`: `[]`内の中立的な区分値。受講グループには使わない。
- `groupTags`: 丸括弧のうち、保守的なグループ形式だけをcanonical表示名へ解決した値。
- `instructors`: `【】`内の講師情報。`専任`や`複数`も許容する。

内部解析ではすべての記号を `rawToken`、`tokenType`、`tokenValue` として保持する。全角・半角丸括弧は同じaliasへ正規化できるが、`[A]`、`(A)`、`【A】`は別種のまま扱う。

## canonical groupと既存設定の移行

新設定は `canonicalGroups` と `groupMappings` に分離した。aliasは `(A)`、`(A組)`のように丸括弧込みで保存するため、角括弧とは衝突しない。複数aliasを同じcanonical groupへ対応できる。

旧 `groupTags` の裸キーは由来を復元できないため自動再利用しない。読み込み時に `legacyGroupTags` へ監査用として保持し、新しいmappingを最初に保存する際は元configをバックアップしてから、旧キーを無効な監査データとして永続化する。今回の作業環境には既存の時間割configファイルがなかったため、実データの移行・削除は発生していない。

## courseId mappingへの影響

course mapping keyは `WEB制作[A]`と`WEB制作[B]`を別キーとして保持する。類似名やベース名だけで同じcourseIdへ自動対応しない。

`data/courses.json`は12 courseで、角括弧付きA/B別タイトルは0件だった。したがって、Excel側のvariantを同じcourseへまとめるか別courseを追加するかは自動決定せず、管理画面で人が個別対応する。variant保持により、dry-runの未登録科目は51種類から54種類になった。

## 管理画面

未知グループの各カードに次を表示する。

- 元のExcel表記（全角・半角双方）と正規化alias
- 使用件数
- subjectRaw、日付、時限、学年、セル位置を含む代表例3件
- 全使用箇所の展開表示
- 既存canonical groupの選択
- 新規canonical group名の入力

`[A]`〜`[D]`はグループ対応から外し、「授業の段階・区分」参考欄へ移した。`【】`も「講師情報・講師表記」の別欄へ表示する。
