# ClassView 時間割インポーター 単発講座・特別授業対応 実装報告

## 実装結果

時間割上の未知名称を、ClassViewの通常授業へ対応・新規登録する以外に、職員が「単発講座・特別授業」「行事・説明会」「試験」「休暇」「その他」へ明示分類できるようにした。分類済み項目は `courseId: null` のまま月別時間割へ保存でき、シラバス授業を無理に作る必要がない。

名称に「講座」などが含まれることを理由とした自動分類、一括分類、本番時間割保存、GitHub公開は行っていない。

## データ設計

`course` と `timetable entry` は別概念として維持した。通常授業はClassViewの授業IDとシラバスを持つが、単発講座・行事・休暇などは時間割entryだけを持てる。

時間割entryの種類は次の6種類である。

| 内部値 | 職員向け表示 | courseId |
| --- | --- | --- |
| `class` | 通常授業 | 必須 |
| `exam` | 試験 | 既存授業との対応あり・なしの両方を許可 |
| `special` | 単発講座・特別授業 | null |
| `event` | 行事・説明会 | null |
| `holiday` | 休暇 | null |
| `other` | その他 | null |

`special` は教育的内容があっても、独立したシラバス授業として登録しない単発講座・外部講師講話などを表す。学生向け公開JSONには表示に必要なentry情報だけを出し、private分類設定やセル位置を含めない。

`relatedCourseId` は今回採用していない。関連授業を自動推測しない要件と、MVPで不要なSchema拡張を避けるためである。職員メモも今回は追加していない。

## 明示mapping

- 通常授業対応: `subjectMappings` に完全な正規化名称から授業IDを保存する。
- 特殊項目分類: `timetableItemMappings` に完全な正規化名称から種類・表示名・更新日時を保存する。
- 保存先: 公開対象外の `runtime/timetable/config.json`。
- バックアップ: 既存どおり変更前のconfigを `backups/timetable/` へ保存し、一時ファイルからatomic置換する。

両mappingへ同じキーを同時登録できない。既存分類を変更するときは確認済みの `replaceExisting` 操作だけが反対側を置き換える。通常授業へ変更する場合、既存授業IDとの対応または新規授業の保存成功が必須で、courseIdなしの通常授業分類は保存できない。

現在の授業対応設定が年度共通であるため、特殊項目分類も年度共通の完全一致キーとした。これにより次年度の同名項目を自動再利用できる。学校での位置づけが変わった場合は個別に分類変更する。すでに保存済みの過去の公開時間割は、対象期間を再取込・保存しない限り変更されない。

## 管理UI

未登録項目カードを次の2領域へ分離した。

- 「シラバスを持つ通常授業ですか？」: 既存授業と対応、新しい授業として登録。
- 「シラバスを持たない単発の予定ですか？」: 単発講座・特別授業、行事・説明会、試験、休暇、その他。

各カードでは、授業段階、使用回数、日付、時限、学年、グループ、講師、教室、Excel原表記、セル位置を表示する。最初の3件を表示し、それ以上は「すべての使用箇所を見る」で展開できる。分類登録前には確認ダイアログを表示し、「その他」には安易な使用を避ける注意を加えた。

「時間割項目の分類」セクションでは、Excel表記、現在の分類、対応するClassView授業、今回の使用回数を確認できる。「分類を変更」から個別に変更できるが、一括削除は提供しない。通常授業へ変更する場合は授業選択または既存のシラバス登録フローへ進む。

分類保存後は保持中のpreviewへmappingを再適用し、Excel再選択なしで未登録科目とblocking件数を即時更新する。

## Schemaと保存

`data/timetable-month.schema.json` に `special` を追加し、条件付き検証を追加した。

- `class`: `courseId` は授業ID形式の文字列。
- `special`、`event`、`holiday`、`other`: `courseId` はnull。
- `exam`: 既存仕様に合わせ文字列またはnull。

serviceが分類をentryへ適用した後、既存の月別Schema検証、一時ファイル検証、atomic置換、バックアップ・rollbackを通る。解析用の `_sourceCell` と `_sourceRow` はpreviewとprivate snapshotだけで使用し、公開JSON作成時に除外する。

## テスト

新たに次を確認した。

- スーツ講座をspecialへ分類するとcourseIdなしでSchema適合すること。
- 同じ完全一致名称の再解析で未登録blockingへ戻らないこと。
- 未分類の通常授業はcourseIdなしのまま保存できないこと。
- event、holiday、otherがcourseIdなしで有効なこと。
- 通常授業対応と特殊項目分類の矛盾を拒否すること。
- 確認済み変更だけがspecialとclassを相互に置き換えること。
- specialからclassへ変更するとき授業IDを要求すること。
- mapping保存失敗をAPIがエラーとして返すこと。
- previewへ再適用してblocking件数を即時更新すること。
- `[A]` と `[C]` のvariant分離と既存の記号解析を維持すること。

Python全154テストが成功した。変更したJavaScriptはNode.jsの構文検証に成功した。

実ブラウザーでは、職員向け分類ボタン、使用文脈、確認ダイアログ、`スーツ講座` の未登録件数1→0、`単発講座・特別授業`から`行事・説明会`への個別変更、変更後の即時表示を確認した。ブラウザーconsoleのerror・warningは0件だった。確認には一時work領域を使用し、本番configを変更していない。
