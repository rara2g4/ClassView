# ClassView 時間割未登録科目からの授業登録 実装報告

## 実装結果

時間割Excelで見つかった未登録科目から、既存のシラバスインポーターを使って授業を1件ずつ作成し、保存成功後にその科目名を作成済み授業IDへ自動対応できるようにした。`After Effects[A]` と `After Effects[C]` のような授業段階は別の科目・別の対応として保持し、ベース名だけを理由に統合しない。

本作業では本番の授業追加、`data/timetable/` の生成・保存、GitHub公開を行っていない。

## 現在の授業登録構造

- 新規授業画面は既存の `/register` を再利用する。時間割専用の第二の登録画面は作成していない。
- シラバスPDFから指定ページを抽出し、ChatGPT用指示文を生成し、返却JSONを編集フォームへ展開する既存フローをそのまま利用する。
- 最終登録は `CourseImporter.register_course()` から `append_course()` を呼び出し、`data/course.schema.json` へ適合することを確認して `data/courses.json` へ1件追加する。
- 保存前にバックアップを作成し、一時ファイルを再検証してから `os.replace()` で置換する既存方式を維持した。
- 授業IDの自動生成規則は存在しないため、既存どおり管理者が半角英小文字・数字・ハイフンで入力する。公開中とアーカイブ済みの両方に対して重複を拒否する。
- 保存された授業だけが通常の未公開変更・プレビュー・GitHub公開フローの対象になる。時間割から登録しても自動公開しない。

## 未登録科目UI

- 実Excelで検出された未登録科目54種類を `subjectBaseName` ごとの51グループに整理した。
- 同じベース科目の授業段階は並べて確認できるが、それぞれ独立したカード・操作を持つ。
- 各カードにはExcel上の完全な授業名、ベース科目、授業段階、使用回数、対象学年、講師情報、日付・時限・学年・グループを含む代表例を最大3件表示する。
- 授業段階のない通常科目も同じカードで扱う。
- 各カードに「既存授業と対応」と「ClassViewへ新規登録」を用意した。一括授業作成・一括対応は実装していない。

## 新規授業作成への引継ぎ

- `title`: Excelの完全な `subjectName` をそのまま使用する。`After Effects[A]` をベース名や別表記へ変換しない。
- `academicYear`: 解析対象の年度候補があり、シラバス側が空欄の場合だけ候補入力する。
- `instructor`: 時間割から一意の文字列として決まる場合、シラバス側が空欄のときだけ候補入力する。複数表記は無理に1件へ確定しない。
- `summary`、`learningGoals`、`classFlow`、`outcomes`、`topics`、`tools`、`assignments`、`schedule`、`suitableFor`、`prerequisites` は時間割から生成しない。
- 時間割由来の3項目は中間メタデータの `sourceType: timetable` と理由で分離する。公開用 `courses.json` へ管理メタデータは保存しない。
- 登録画面上部には対象科目、授業段階、使用回数、講師情報を軽い案内として表示する。通常のPDF・ChatGPT・編集・検証フローは変更しない。

## 授業との対応

- 明示対応は既存の非公開設定 `runtime/timetable/config.json` の科目対応表へ保存する。
- 対応キーは正規化済みの完全な `subjectName` であり、`subjectBaseName` ではない。
- 授業保存成功後にだけ、今回の対象科目1件を保存済み授業IDへ対応させる。他の授業段階へは波及しない。
- 授業保存失敗時は対応を作らない。キャンセル時も対応を作らない。
- 授業は作成できたが対応保存だけ失敗した場合、HTTP 409と「授業は作成済み・対応は未完了」の情報を返して画面へ明示する。コンテキストは再試行できる状態で残す。
- 対応先授業が削除またはアーカイブされた場合は `対応先授業が見つかりません` のblockingとし、公開中の授業だけを新しい対応先として選択可能にした。

## 既存授業への対応

- `subjectName` と公開中授業の `title` が完全一致し、候補が1件だけなら確認用候補と「この授業と対応」を表示する。表示だけでは保存せず、管理者操作を必須にした。
- ベース名だけが一致する授業は「関連する名前の授業」として注意付きで表示し、推奨・自動対応しない。
- 一覧から別の公開中授業を人が選べるため、確認済みの表記揺れを同じ授業IDへ複数対応させることは可能である。

## 解析状態の保持

- 解析プレビュー、科目使用例、比較元をサーバー内の期限付きメモリ状態として保持する。
- 登録画面へは推測困難なコンテキストトークンだけをURLで渡し、科目名や解析内容をqueryへ直接入れない。
- 新規授業登録後またはキャンセル後は `/timetable?preview=<token>` へ戻れる。Excel原本を再選択せず解析結果を復元する。
- 対応登録後はExcelを先頭から読み直さず、保持中のentryへ最新対応を再適用して問題一覧、差分、件数を更新する。
- プレビューと登録コンテキストは2時間で失効し、管理ツール再起動後は再解析が必要になる。公開 `data/` へ解析状態やExcel原本を保存しない。

## テスト結果

次の新規ケースを追加した。

- `[A]` と `[C]` が別カード・別対応であること
- ベース名一致を自動対応しないこと
- 完全一致候補を表示しても自動保存しないこと
- 授業保存成功後だけ対応を作り、対象の授業段階だけ未登録から消えること
- 授業保存失敗時に対応を作らないこと
- 対応保存失敗時に授業作成済みを明示すること
- キャンセル時に対応を作らないこと
- 登録画面との往復後にプレビューを復元できること
- 削除・アーカイブ済みの対応先をblockingにすること
- 時間割メタデータをtitle・academicYear・instructorだけに制限すること

Python全テストは次のコマンドで実行し、148件すべて成功した。

```powershell
py -3 -m unittest discover -s tools/course-importer/tests -p 'test_*.py'
```

変更した `app.js`、`timetable.js`、`editor-state.js` はNode.jsの `--check` でも構文エラーがないことを確認した。

実ブラウザーでは実Excelをアップロードし、54カードが51ベース科目グループに表示されること、`After Effects[A]` と `[C]` が各29回の独立カードになること、新規登録画面に `[A]` の文脈だけが表示されること、授業ID欄が自動生成されないこと、キャンセル後にExcel再選択なしで解析結果が復元されることを確認した。実授業の最終保存は行っていない。

未登録科目を実際の授業へまだ対応していないため54種類が残るのは正常である。`After Effects[A]` と `After Effects[C]` はそれぞれ29回使用され、別の未登録科目として維持されている。
