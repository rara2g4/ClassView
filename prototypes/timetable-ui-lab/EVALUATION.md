# 時間割UI比較評価

## 前提

- 8案は同一の既存デモcourse・時間割fixtureを使用する。
- PC週間は保存済み個人時間割、PC日表示と高密度確認は学校全体、スマホは保存済み個人時間割で比較する。
- 評価は「観測できる操作・レイアウト上の性質」と「好みが影響する印象」を分ける。
- 数値は5段階の相対評価で、5が最も有利。実装複雑さだけは5が最も複雑。

## 客観的に確認できる長所・短所

### A案：現行整理型

- 長所: DOMの読み順と視覚順が一致し、キーボード・スクリーンリーダーでも理解しやすい。長い名称と多数カードを安全に縦へ逃がせる。
- 短所: 週間表示では曜日×4時限が縦に続き、後半曜日へ到達するスクロール量が最大になる。
- 現行比: 情報階層は改善できるが、時間割の構造自体を再発明する案ではない。

### B案：週間グリッド型

- 長所: 曜日・時限・空き枠の位置が固定され、1週間の形を最速で把握できる。
- 短所: 同時限に6〜10件あるセルは高さが伸び、列幅が限られるため長い名称に弱い。スマホでは横移動が避けにくい。
- 現行比: PC個人時間割には強いが、学校全体の高密度データでは現行より読みにくくなる場合がある。

### C案：高密度ダッシュボード型

- 長所: 1行1授業で一覧走査でき、同時限の多数候補や担当・教室の比較に強い。スクロールあたりの情報量が最大。
- 短所: 時間割の「空き」や位置関係より検索リストに近く、初見の学生には視線の開始点が多い。
- 現行比: 学校全体表示や職員確認には有力だが、日常的な個人時間割には過剰な可能性がある。

### D案：時間軸カレンダー型

- 長所: 開始・終了時刻と一日の流れが視覚的位置に対応し、一般的なカレンダー経験を活用できる。
- 短所: ClassViewの授業は4つの大きな時限に集中するため、一般カレンダーほど時間軸の利点が出ない。同時限多数でブロックが細分化する。
- 現行比: 個人時間割は魅力的だが、学校全体表示は現行より不利。

### E案：曜日ボード型

- 長所: 授業カードの可読幅を保ち、曜日単位のまとまりと授業単位の認識を両立する。件数増加は列内スクロールとして扱いやすい。
- 短所: 曜日列の高さが不均一になり、同じ時限を横断比較する視線がずれやすい。
- 現行比: 情報の多い学校全体表示に対応しやすいが、空き枠の一覧性は週間表に劣る。

### F案：分割ペイン型

- 長所: 曜日選択・当日詳細・週間密度を同時に保持し、移動しても現在地を見失いにくい。長い名称の表示領域も確保できる。
- 短所: 3領域の幅調整とフォーカス管理が必要で、レスポンシブ実装と保守が複雑。
- 現行比: PCでの探索効率は大きく改善する可能性があり、スマホでは曜日タブ＋当日一覧へ構造を変える必要がある。

### G案：路線図型

- 長所: 1限から4限へ進む順序と空き時間を強く意識でき、時系列の読み物として分かりやすい。
- 短所: 曜日間・同時限間の厳密比較は表より遅く、装飾面積も増える。
- 現行比: 学生の「今日の流れ」には適するが、学校全体の実用一覧としては現行に劣る。

### H案：フォーカス＋ミニマップ型

- 長所: 390pxでも週の密度と1コマの候補を両立でき、多数候補・長い名称を広い詳細領域で扱える。タップ対象も大きい。
- 短所: 授業名を週全体で同時比較できず、20枠を順番に読む操作数は増える。
- 現行比: スマホで有力。PCでは空間を使い切らず、B/F案より一覧性が低い。

## 好みが影響する点

- C案の暗い高密度画面を「集中できる」と見るか「学校サービスらしくない」と見るか。
- D案のカレンダー表現を馴染みやすいと見るか、4時限制には過剰と見るか。
- G案の路線図表現を親しみやすいと見るか、装飾的と見るか。
- 角の少ないA/B/F案を堅実と見るか、硬いと見るか。

## Human reviewで確認したい組み合わせ

1. PC個人時間割: B案とF案を比較する。
2. PC学校全体: C案とE案を比較する。
3. スマホ個人時間割: A案とH案を比較する。
4. 日表示の体験: D案とG案を比較する。

この評価は採用決定ではありません。実際の学生が最も頻繁に使う「個人の日表示」と、授業探索に使う「学校全体の週間表示」を同一UIにするか、表示目的ごとに構造を分けるかがHuman review上の主要論点です。
