# ClassView シラバスインポーター

ClassViewへ授業データを継続的に登録するための、ローカル専用のシラバス作成支援ツールです。単なるPDFからJSONへの変換ではなく、既存シラバスを基礎資料としてAIが質の高い授業情報の下書きを作り、シラバス作成者が採用・修正・不採用を判断して完成させます。GitHub Pages上では動作せず、公開サイトの画面や機能にも影響しません。

AIの出力を正解として自動登録するツールではありません。シラバスの事実、シラバス内からの推察、一般的な専門知識を使ったAI下書き提案を明確に分け、未確認のAI提案が残っている間は登録できません。人が最終確認したClassView用授業データだけを `data/courses.json` へ保存します。

このツールはChatGPT APIを使用しません。ChatGPTを開くリンクだけを提供し、PDFの添付、指示文の送信、返答の貼り付けは利用者が手動で行います。

## 初回セットアップと起動

Windowsでは、リポジトリ内の次のファイルをダブルクリックするのが簡単です。

```text
tools/course-importer/run-course-importer.bat
```

初回だけ仮想環境を作成して必要なライブラリをインストールします。準備後、ブラウザで `http://localhost:5050` が開きます。

PowerShellやコマンドプロンプトから手動で準備する場合は、リポジトリのルートで次を実行してください。

```text
python -m venv tools/course-importer/.venv
tools\course-importer\.venv\Scripts\python -m pip install -r tools/course-importer/requirements.txt
tools\course-importer\.venv\Scripts\python tools/course-importer/app.py
```

すでに依存ライブラリを利用できるPython環境では、次の起動方法も使用できます。

```text
python tools/course-importer/app.py
```

停止するときは、起動したターミナルで `Ctrl+C` を押してください。待受先は `127.0.0.1` のみです。ポートを変更する場合は、環境変数 `CLASSVIEW_IMPORTER_PORT` を設定します。

## 職員向けの通常運用

起動後の管理ホームでは、授業データ、公開設定、公開サービス接続、最新状態、バックアップを自動確認します。職員が行う通常操作は次の流れだけです。

1. 管理ツールを起動する
2. 「新しい授業を登録」または「授業を管理」を選ぶ
3. 授業情報を保存する
4. 管理ホームの「未公開の変更」を確認する
5. 「ClassViewへ公開」を押す
6. 公開完了後に「公開サイトを開く」で確認する

授業情報の保存と公開は分離されています。保存しただけでは公開サービスへ送信されず、管理ホームに「未公開の変更」として残ります。職員向けの詳しい手順は [`../../docs/ClassView_操作マニュアル.md`](../../docs/ClassView_操作マニュアル.md) を参照してください。

## 初回セットアップと公開設定

初回だけ、開発者または管理担当者が次を準備します。

- ClassViewリポジトリを管理PCへ配置
- Git for WindowsとGit Credential Managerをインストール
- 公開用アカウントで認証
- `tools/course-importer/classview-admin.json` の確認
- 必要に応じてWindows実行ファイルとデスクトップショートカットを作成

公開設定は `classview-admin.json` だけに集約します。

| 項目 | 意味 |
| --- | --- |
| `remoteName` | 公開先として使用する接続設定名。通常は `origin` |
| `expectedBranch` | GitHub Pagesの公開元として運用するブランチ |
| `expectedRemoteUrl` | 想定するリポジトリURL |
| `publicUrl` | 管理画面の「公開サイトを開く」で使用するURL |

アクセストークン、パスワード、秘密鍵はこの設定ファイルへ保存しません。認証にはGit for Windowsの既存認証機構を使用します。GitHub Organizationへ移管する場合は、リポジトリ側の接続設定を変更したうえで、`expectedRemoteUrl` と `publicUrl` を更新します。Pythonコードの修正は不要です。

## 最新状態確認と安全な同期

管理ホームを開いたときと「最新状態を確認」を押したときに、次を確認します。

- Gitが利用できること
- ClassViewリポジトリであること
- 接続先とブランチが設定どおりであること
- 授業JSONがSchemaに適合すること
- このPCの変更と公開側の変更の有無

公開側だけが進んでおり、このPCに変更が一切ない場合は、`fetch` 後に `merge --ff-only` で安全に取得できる場合だけ更新します。このPCに未公開変更がある場合は自動更新しません。両方に変更がある場合や履歴が分岐した場合も、自動rebase、自動競合解決、強制checkout、`reset --hard` は行わず、公開を停止して管理担当者への確認を案内します。

## ClassViewへの公開処理

「ClassViewへ公開」を押すと、次の順序で処理します。

1. 公開中とアーカイブの全授業をSchema検証
2. 接続先、ブランチ、公開側との差異を再確認
3. 公開対象を確認
4. 許可された授業データだけを明示的に準備
5. 人間が読める公開履歴を作成
6. 通常のpushで公開先へ送信

自動公開で許可するファイルは、コード内の固定リストにある次の2ファイルだけです。

```text
data/courses.json
data/archived-courses.json
```

`git add .` は使用しません。Python、CSS、JavaScript、README、テスト、その他の作業ファイルは、職員の公開操作に含まれません。すでに別のファイルが公開準備中の場合も処理を停止します。

状態確認・同期・公開に使うGitコマンドはすべて共通の `run_git` から、`run_hidden_process(["git", ...])` の配列形式で実行します。Windowsでは `CREATE_NO_WINDOW` と非表示の `STARTUPINFO` を共通適用し、起動時確認、状態確認、fetch、add、commit、pushの途中で黒いコンソール画面を表示しません。Windows以外ではWindows専用設定を渡しません。stdout、stderr、終了コードは従来どおりPython側で取得します。

シェルは常に無効で、授業名や操作内容をシェル文字列へ連結しません。`cmd /c`、`os.system`、`git add .` は使用していないため、特殊文字を含む授業名もコマンドとして解釈されません。`push --force`、自動rebase、強制checkout、自動競合解決も実装していません。

公開メッセージは、変更が1件なら授業名と変更内容、複数なら件数から自動生成します。pushに失敗しても、ローカルの授業データと自動バックアップは残ります。作成済みの公開履歴がローカルに残った場合は、状態確認後に再度公開できます。

## 職員向けエラーと診断情報

通常画面では、生のGitエラーではなく「インターネットに接続できません」「公開サービスへのログインが必要です」「公開サイト側に新しい変更があります」などの職員向け文言を表示します。

保守担当者向けには「技術情報を表示」と「診断情報をコピー」を用意しています。診断情報には処理名、終了コード、ブランチ、接続先、標準エラーを含めますが、URL内の認証情報、トークンらしき文字列、password・secretなどの値はマスクします。

操作ログは `tools/course-importer/logs/admin.log` に保存します。起動、保存、公開、公開失敗などを記録し、1ファイル1MB、3世代でローテーションします。認証情報は記録しません。`logs/` はGit管理対象外です。

## Windows実行ファイルとショートカット

開発者は次のファイルを実行して、Windows向けの1ファイル実行形式を作成できます。

```text
tools/course-importer/build_windows.bat
```

初回ビルド時に `requirements-build.txt` のPyInstallerを開発用仮想環境へインストールし、次を生成します。

```text
tools/course-importer/dist/ClassView管理ツール.exe
```

実行ファイルはリポジトリ内の `tools/course-importer/dist/` に置いたまま使用してください。実行場所からリポジトリルートを解決し、`data/`、Schema、バックアップ、設定を参照します。テンプレートと画面用ファイルは実行ファイルへ同梱されます。

ビルド後に次を1回実行すると、職員のデスクトップへショートカットを作成します。

```text
tools/course-importer/install_windows_shortcut.bat
```

実行ファイルはPyInstallerの `--noconsole` で作成され、コンソールを表示せずにローカル管理画面をブラウザで開きます。Flaskは実行ファイル自身のプロセス内で動作し、別のcmd.exeやPythonを起動しません。既定の5050番ポートが使用中なら、5051番以降の空いているlocalhostポートを安全に選びます。待受先は常に `127.0.0.1` であり、校内ネットワークやインターネットへ管理画面を公開しません。終了時は管理ホーム右上の「終了」を押してください。

`run-course-importer.bat` と `python tools/course-importer/app.py` は開発・保守用です。こちらは調査に必要なログを端末へ表示します。職員の通常運用では、コンソールを表示しない実行ファイルまたはそのデスクトップショートカットを使用してください。

公開サービスへの認証が切れた場合は、通常のfetchやpushで端末入力を求めず、管理画面に再ログインが必要であることを表示します。「公開サービスへ再接続」を押したときだけ、Git Credential Managerの公式認証を非表示プロセスで開始します。認証用ブラウザは必要な利用者操作なので通常どおり表示されます。処理失敗時は管理画面の職員向けメッセージと技術情報に結果を返し、認証情報やトークンはログへ記録しません。

## 二重起動の防止

Windows版は `Local\Rara2g4.ClassView.ManagementTool.SingleInstance.v1` というClassView固有のNamed Mutexを起動中だけ保持します。これはWindowsが管理するロックなので、通常終了だけでなくタスクマネージャーからの強制終了や異常終了でもOSが自動解放します。単純なlockファイルの有無だけで起動を止める方式ではありません。

初回起動時は、Mutex取得後にFlaskサーバーを1つだけ起動します。実行中の情報はGit管理外の `tools/course-importer/runtime/classview-instance.json` へ次の3項目だけ保存します。

```json
{
  "pid": 12345,
  "port": 5050,
  "instanceId": "起動ごとに変わる識別子"
}
```

認証情報、ファイルパス、利用者情報は保存しません。2回目以降のexeはMutexを取得できないため、新しいFlaskサーバー、Git同期、授業JSON更新を開始しません。状態ファイルから既存URLを読み、`/api/health` のアプリ名と `instanceId` が一致することを確認して、既存の管理画面をブラウザで開いた後に終了します。1個目が起動途中の場合に備え、health確認は約5秒間だけ再試行します。

Mutexを取得できたのに以前の状態ファイルだけが残っている場合、そのファイルは異常終了時の古い状態と判断して自動削除し、新しい状態を作成します。Mutexが存在するのに既存画面へ接続できない場合は、別サーバーを立てたり既存プロセスを強制終了したりせず、職員向けの再試行案内を表示します。

管理ホームの「終了」は、保存・公開・認証・最新状態確認が実行中なら「処理が完了するまで終了できません」と表示して停止を拒否します。終了可能な場合は組み込みサーバーを正常停止し、状態ファイルを削除してからMutexを解放します。ブラウザだけを閉じても本体は動作を続けますが、exeをもう一度押せば同じ管理画面を開き直せます。

Windows以外では同じ役割をOSのファイルロックで実現します。Windows専用のMutex APIやプロセス生成設定はWindows以外へ渡しません。

## 公開履歴と復元

管理ホームの「公開履歴」は、授業データに関係する最近の履歴を職員向けの日時と説明に変換して表示します。

過去状態へのワンクリック復元は今回実装していません。危険な履歴書き換えを避けるためです。授業操作前のJSONバックアップは従来どおり維持されているため、必要な場合は管理担当者が過去内容を確認し、新しい変更として再適用してから通常の公開操作を行います。

## 登録手順

1. 「シラバス作成支援」または「厳格変換」を選び、シラバスPDF、授業情報の掲載ページ、新しい授業IDを入力します。単一ページは `42`、連続範囲は `42-43` と指定します。
2. 「抽出ページと指示文を準備」を押します。ページ範囲とIDが検証され、指定したページを元PDFと同じ順序でまとめたPDFが一時領域に作成されます。
3. 抽出PDFを開いて対象ページを確認し、必要ならダウンロードします。
4. AI用変換指示文をコピーします。
5. 「ChatGPTを開く」から新しいチャットを開き、抽出PDFを添付して指示文を送ります。
6. ChatGPTが返した `course` と `fieldMeta` を持つ中間JSONを貼り付け、「JSONを検証してフォームへ反映」を押します。JSON構文、情報源メタデータ、Schema、ID、重複の検証に合格すると、内容が編集フォームへ展開されます。従来の授業JSON単体も移行用として取り込めます。
7. 「未入力」の項目を必要に応じて補完し、「シラバスから取得」「シラバスから推察」の項目も必要なら修正します。AI下書き提案は、各項目で「このまま採用」「修正して採用」「使用しない」のいずれかを判断します。
8. 右側のライブプレビューで公開時の情報構造を確認します。未確認提案が含まれる場合は管理画面内だけに注意を表示します。デスクトップでは編集欄と並び、スマートフォン幅では縦に並びます。
9. 「編集内容を最終検証」を押します。フォームからClassView用JSONを内部生成し、現在のSchema、準備時のID、ID重複を再検証します。
10. シラバスからの推察が残っている場合は、対象一覧とフォーム上の推察根拠を読み、確認チェックを入れます。AI下書き提案はすべて判断済みでなければ最終検証を通過しません。その後「ClassViewへ追加」を押すと、追加直前にも検証済みデータとの一致、Schema、重複、確認状態を検証し、バックアップ作成後に追記されます。
11. 登録後は `git diff -- data/courses.json` で差分を確認してください。このツールはGitのコミットやpushを行いません。

フォームを変更すると最終検証結果は失効し、「ClassViewへ追加」は再び無効になります。必ず再検証してください。生成されるJSONは「高度な確認：現在のJSONを見る」で読み取り専用表示できます。

## 既存授業の管理

画面上部の「授業管理」から、すでに登録されている授業を継続運用できます。公開中の授業は `data/courses.json`、アーカイブ済み授業は `data/archived-courses.json` に保存されます。公開ClassViewが読み込むのは従来どおり `courses.json` だけです。

授業管理画面では、授業名、ID、年度、講師、分野を1つの検索欄から検索できます。一覧は授業名、同名授業の年度降順、IDの順で整理され、公開中とアーカイブをタブで切り替えます。

### 既存授業を編集する

1. 「授業管理」で公開中の授業を検索します。
2. 「編集」を押すと、現在の授業データが人間向け編集フォームとライブプレビューへ読み込まれます。
3. 必要な項目を変更します。授業IDは読み取り専用で、変更できません。
4. 変更点欄でフィールド単位の差分を確認し、「変更を保存」を押します。

保存時には、対象授業が現在も存在し、読み込み後に別の操作で変更されていないこと、IDが同じこと、現在のSchemaに適合することを再確認します。合格後に `courses.json` のバックアップを作成し、対象IDの授業だけを置換します。他の授業の並びと内容は維持します。

`academicYear` の誤記訂正は編集できますが、継続開講の年度更新に「編集」を使用しないでください。年度履歴を残すため、次の「次年度へ引き継ぐ」を使用します。

### 次年度へ引き継ぐ

年度更新は、既存授業の `academicYear` を直接書き換える操作ではありません。必ず次の流れで、前年度版を残したまま新年度版を作成します。

```text
前年度版を選択
↓
次年度へ引き継ぐ
↓
コピーされた内容を確認・修正
↓
新しいIDを持つ新年度版として追加
```

`academicYear` が `2026` または `2026年度` のように解釈できる場合は、初期値を `2027` にします。元IDが `basic-information-1-2026` なら `basic-information-1-2027`、年度を含まない `basic-information-1` なら `basic-information-1-2027` を候補にします。候補が公開中またはアーカイブに存在する場合は、`-2` などを付けた未使用候補を提示します。年度を解釈できない場合はIDと年度を空欄にし、管理者の入力を求めます。

講師、概要、授業計画などは前年度版からすべてコピーされます。管理者は新年度版のフォームで自由に修正できます。変更点欄には、年度や講師などの変更前後、配列項目の変更件数が表示されます。年度以外の内容が同じでも、新しいIDと年度があれば別授業として登録できます。保存直前に前年度版の内容が変わっていないことを再確認し、新年度版だけを `courses.json` へ追記します。

### アーカイブと復元

公開を終了する通常操作には「アーカイブ」を使用します。確認画面で授業名、年度、講師、IDを確認すると、授業を `courses.json` から `archived-courses.json` へ移動します。公開サイトからは表示されなくなりますが、データは残ります。

アーカイブタブの「公開授業へ戻す」で逆方向へ移動できます。復元前にSchemaとIDを検証し、公開中に同じIDがある場合は復元を禁止します。「内容を見る」ではアーカイブ授業を読み取り専用フォームとプレビューで確認できます。

### 完全削除

完全削除はアーカイブ済み授業だけに表示される危険な操作です。確認画面を経て、指定した授業だけを `archived-courses.json` から削除します。日常的な公開終了には完全削除ではなくアーカイブを使用してください。削除前にもバックアップを作成します。

### 管理操作のバックアップと安全性

編集、次年度版追加、アーカイブ、復元、完全削除のすべてで、操作内容を含む名前のバックアップを `tools/course-importer/backups/` へ作成します。例は `courses-edit-授業ID-日時.json`、`courses-rollover-元ID-to-新ID-日時.json`、`archived-courses-delete-授業ID-日時.json` です。

アーカイブと復元は2つのJSONを変更するため、両ファイルを先にSchema検証し、両方のバックアップと一時ファイルを準備してから置換します。途中で失敗した場合は、置換済みのファイルをバックアップから戻します。さらに、画面へ読み込んだ時点の授業ハッシュを保存し、保存直前の授業と一致しない場合は操作を中止します。

## 編集フォームとSchemaの役割

`data/course.schema.json` が保存可能なフィールド、データ型、必須条件、文字数や形式の正式な仕様です。フォーム側で管理するのは、日本語の項目名、短文・長文・配列などの入力UI、説明文だけです。必須表示と最終検証はSchemaから取得し、型情報をフォーム側へ二重定義しません。

`data/course.template.json` は、AIのJSONで省略された項目をフォーム状態へ補うときと、空欄を最終JSONへ戻すときの基準です。`category`、`grade`、`academicYear`、`instructor`、`courseType`、`classStyle` の入力候補は、起動時に現在の `data/courses.json` から重複を除いて生成します。候補外の値も入力できます。

`instructor` は講師名、`academicYear` は授業情報の基準年度です。どちらも任意項目で、空欄のままでも登録できます。年度はファイル名から自動確定せず、AIがPDFから取得した値または管理者が確認して入力した値だけを使用します。フォームとプレビューでは「講師名」「年度」として表示し、年度のプレビューには「年度」を付加しますが、JSONの値は `"2026"` のままです。

## 変換モード

- `シラバス作成支援`（標準）: シラバスの事実と合理的推察を優先し、不足部分には科目の一般的な専門知識と教育設計を使った完成形の下書きを `proposed` として提案します。
- `厳格変換`: シラバスに直接記載された情報と、同じシラバス内から高い確度で直接導ける情報だけを使います。`proposed` は許可しません。

どちらのモードでも、担当者、年度、学年、必修・選択、具体的な教材・ソフトウェア、授業回、評価割合、提出頻度、実施回数などの事実を根拠なく作成しません。元シラバスと一般知識が矛盾する場合は、元シラバスを優先します。

## 情報源・推察・AI下書き提案

ChatGPTは、どちらのモードでもシラバスに直接書かれた情報を最優先します。直接の文章がなくても、同じシラバス内の記載から合理的に直接導ける場合は `inferred` として整理できます。シラバス作成支援では、科目の一般的な専門知識や教育設計を使用した内容を事実と混同せず、`proposed` の下書きとして提案できます。

標準の中間JSONは次の構造です。

```json
{
  "course": {
    "id": "programming-basic",
    "outcomes": "Pythonの基本機能を用いて簡単なプログラムを作成できる。"
  },
  "fieldMeta": {
    "outcomes": {
      "sourceType": "inferred",
      "reason": "授業概要と条件分岐・繰り返し・リスト・関数・辞書を扱う授業計画から導出"
    },
    "classFlow": {
      "sourceType": "proposed",
      "reason": "授業内容と一般的な初学者向けプログラミング教育の構成を参考に提案"
    }
  }
}
```

実際の中間JSONでは、Schemaの全フィールドについて `fieldMeta` を返します。各項目には管理画面だけの状態が表示されます。

- `シラバスから取得`（`explicit`）: シラバスに直接記載された情報、または管理者が登録用IDとして明示した値
- `シラバスから推察`（`inferred`）: 同じシラバス内の具体的な記載から、外部知識なしで直接導いた情報。フォーム上に推察根拠を表示
- `AI下書き提案`（`proposed`）: 元シラバスを基礎資料とし、一般的な専門知識や教育設計も使った提案。フォーム上に提案理由と確認操作を表示
- `未入力`（`missing`）: シラバスに情報がなく、AI提案としても無理に書くべきでない空欄
- `手動修正`: 取り込み後に管理者が値を変更または削除した項目

状態、推察・提案理由、`fieldMeta`、AI提案の確認状態は管理画面内だけで使用します。プレビューには公開される授業文章だけを表示し、`courses.json` へ保存する際は `course` だけを取り出します。

シラバス内からの推察を許可する主な項目は `summary`、`learningGoals`、`outcomes`、`topics`、条件を満たす `suitableFor`、`assignments`、`classFlow` です。シラバス作成支援のAI提案は `summary`、`learningGoals`、`outcomes`、`classFlow`、`prerequisites`、`suitableFor`、`assignments`、`category`、`classStyle` に限定します。`id`、`title`、`instructor`、`academicYear`、`grade`、`courseType`、`tools`、`schedule`、`images` はAI提案で設定できません。

学習内容を分けて確認するときは、次の役割を使用します。

- `learningGoals`: 何を学ぶ授業なのか。授業の目的や学習対象
- `topics`: 具体的にどの分野・テーマを扱うのか
- `classFlow`: 講義、演習、制作など、どのように学ぶのか
- `outcomes`: 学んだ結果として身につく知識・理解・技能・遂行能力

`outcomes` は編集フォームと公開プレビューで「身につく知識・できるようになること」と表示します。「〜について学ぶ」「〜を扱う」だけで終わる学習内容の説明ではなく、シラバスの根拠に応じて「理解できる」「説明できる」「使用できる」「作成できる」「基礎知識を身につける」など、授業終了時の学生の状態を記述します。合理的に導けない場合は無理に生成せず、`missing` のままにします。

## AI下書き提案の確認状態

`reviewStatus` 相当の状態はAIに生成させず、フォーム内の `proposalReviews` としてcourse-importerが管理します。

- `pending`: AIが生成した直後で、人がまだ判断していない
- `accepted`: 「このまま採用」を選び、提案本文をそのまま使用する
- `edited`: 「修正して採用」または入力欄の編集により、管理者が修正した本文を使用する
- `rejected`: 「使用しない」を選び、値をテンプレートの空値へ戻して最終授業データから除外する

画面上部の確認状況には提案ごとの状態を一覧表示しますが、内容を見ずに一括自動採用する操作はありません。`pending` が1件でも残っていると「AI下書き提案がn件未確認です」と表示され、最終検証と登録を通過できません。右側プレビューにも管理画面内だけで「未確認のAI提案を含むプレビュー」と表示します。公開ClassViewには情報源や確認状態を表示しません。

## 配列・授業回・画像の編集

`topics`、`tools`、`assignments` は項目ごとの入力欄として表示され、追加・削除ボタンで編集できます。空の行は最終JSONの空文字として保存しません。

`schedule` は、授業回、内容、補足説明を1組とする専用入力欄です。追加・削除ができ、プレビューでは `session` が `1` なら「第1回」、`1〜2` なら「第1〜2回」と表示されます。JSON内の `session` 自体は変更しません。

AI変換時は、連続する授業回の内容表記が完全に同じ場合だけ、`1`、`2`、`3`を`1〜3`へまとめます。途中に別内容がある場合は範囲を分け、似ているだけの内容、異なる補足がある回、離れた回はまとめません。この圧縮は新しくAI変換するデータだけに適用し、既存の `courses.json` は自動変更しません。

## ページ指定

- `42`: 元PDFの42ページだけを抽出します。
- `42-43`: 元PDFの42ページと43ページを、この順序で1つのPDFへまとめます。
- `42-44`: 3ページ以上の連続範囲も同じ形式で指定できます。

開始・終了ページは1以上、開始ページは終了ページ以下である必要があります。PDF総ページ数を超える指定、不正な文字列、カンマを使った非連続指定は拒否します。誤操作や過大なAI入力を避けるため、1回に抽出できる範囲は最大20ページです。複数ページの場合、生成する指示文には「すべて同一授業のシラバスであり、ページをまたいだ情報を統合する」ことが自動的に追記されます。

`images` は「追加情報：授業風景・画像」の折りたたみ領域で、画像パス、代替テキスト、説明を編集できます。実際のファイルアップロード機能ではないため、公開サイトから参照できる相対パスを入力してください。

## 授業IDのルール

授業IDの正規表現をツール内へ重複定義せず、起動時と入力時に `data/course.schema.json` の `properties.id.pattern` を読み取ります。現在の規則は次のとおりです。

```text
^[a-z0-9]+(?:-[a-z0-9]+)*$
```

使用できるのは半角英小文字、数字、区切りのハイフンです。先頭・末尾のハイフン、連続するハイフン、大文字、アンダースコアは使用できません。`data/courses.json` または `data/archived-courses.json` に同じIDがある場合も準備・検証・登録の各段階で拒否されます。

## 検証内容

- AIから受け取ったJSONが解析できること。構文エラーでは行番号と列番号を表示します。
- 新形式の `fieldMeta` にSchemaの全項目があり、`sourceType` が `explicit`、`inferred`、`proposed`、`missing` のいずれかであること。
- `inferred` に空でない推察根拠があり、推察可能なフィールドだけで使用されていること。
- `proposed` に空でない提案理由があり、シラバス作成支援モードの提案可能フィールドだけで使用されていること。
- 厳格変換で `proposed` が使用されていないこと。
- `proposed` の全項目が `accepted`、`edited`、`rejected` のいずれかに判断され、`pending` が残っていないこと。
- `accepted` はAI原案から変更されておらず、`edited` は原案から変更された値が残り、`rejected` は空値になっていること。画面表示だけでなくサーバー側でも確認します。
- `data/course.schema.json`（Draft 2020-12）に適合すること。
- JSONの `id` が準備時に指定した授業IDと完全に一致すること。
- 登録済みの授業IDと重複しないこと。
- Schemaにないフィールドが含まれていないこと（Schemaの `additionalProperties: false` による検証）。
- フォーム編集後の最終データが同じSchemaへ再度適合すること。
- 最終検証後から登録まで授業データが変更されていないこと。
- シラバスからの推察が残る場合、管理者が推察項目と根拠を確認済みであること。

Schemaを唯一の公開データ仕様として毎回読み直すため、将来Schemaが更新された場合も再起動後のツールへ反映されます。AI用指示文には、選択モード、現在の分野候補、授業ID、Schema、テンプレートが含まれます。事実・推察・提案の区別、具体的な事実や数値の創作禁止、JSON以外を出力しないことも明記されます。

## 追加とバックアップの仕組み

新規登録時は `data/courses.json` をメモリ上で読み込み、既存の `courses` 配列の末尾へ新しい授業を1件だけ追加します。授業の並び順とオブジェクト内のフィールド順を保ち、日本語をUnicodeエスケープへ変換せず、既存と同じ2スペースインデントおよびファイル末尾の改行有無を維持して保存します。授業管理の更新も同じSchema、JSON形式、一時ファイル検証を使用します。

書き込み前に次の形式でバックアップを作成します。

```text
tools/course-importer/backups/courses-YYYY-MM-DD-HHMMSS.json
```

新しい内容は同じディレクトリの一時ファイルへ書き、フラッシュ、再読込、内容一致の確認を行ってから `os.replace` で置き換えます。置換前に失敗した場合、元の `courses.json` は変更されません。バックアップ、一時PDF、アップロード、一時ファイル、Python仮想環境は `.gitignore` の対象です。

## セキュリティとデータの扱い

- サーバーは `127.0.0.1` だけで待ち受け、localhost以外からのリクエストを拒否します。
- 拡張子とPDFヘッダーを確認し、`pypdf` で読めないファイルを拒否します。
- PDFの上限は512MBです。パスワード付きPDFには対応しません。
- ページ指定は1以上の単一ページまたは連続範囲で、PDFの総ページ数以内かつ最大20ページである必要があります。
- アップロード名は保存パスに使用しません。作業用ディレクトリには推測困難なランダムIDを使います。
- 授業IDをパスに使う前にSchemaの形式で検証します。
- 元の巨大PDFはページ抽出後に削除し、指定したページだけをまとめた抽出PDFを `tools/course-importer/tmp/` に一時保存します。
- 一時ファイルやバックアップは公開用ディレクトリではなく、Gitの追跡対象外です。

作業が終わった後、一時PDFが不要なら `tools/course-importer/tmp/` の内容を削除できます。バックアップは必要な期間だけ手元に保管してください。

```text
node tools/course-importer/tests/test_editor_state.js
```

- 正しい授業IDと不正な授業ID

- JSON構文エラー
- Schema違反

- AI生成JSONからフォーム状態への展開
- 新旧両方のAI応答形式
- `explicit`、`inferred`、`proposed`、`missing` と推察・提案理由の検証
- 厳格変換とシラバス作成支援のモード別制約
